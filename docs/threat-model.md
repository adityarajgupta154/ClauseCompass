# Threat model

What ClauseCompass protects, where trust changes hands, and the guarantees the code has to keep. It is a reference for changes and reviews, not a task list; the controls that enforce each guarantee are named so a change can be checked against them. Companion documents: [`SECURITY.md`](../SECURITY.md) (reporting and the controls in one page), the README's *Security controls* section, and [`architecture.svg`](architecture.svg) (the data flow). Checked against the code on 17 September 2026.

## Project overview

A reader uploads one contract (or two versions of one) and gets a source-linked reading of it: a document map, review prompts, a timeline, a version comparison and a printable packet, with official helplines for situations the document cannot help with. React 19 + Vite in the browser; an Express 5 API in one Node process, memory only, no database; PDF/DOCX/TXT parsed in worker threads; plain-language restatements from the Anthropic Messages API (Claude Haiku by default); sign-in through Firebase Authentication (Google, e-mail and password). Readers are members of the public reading their own rent agreement, job offer or NDA, often on a phone, sometimes under pressure. There are no roles: every signed-in reader has the same powers over their own session and none over anyone else's.

## Assets

- **The document.** The most sensitive thing in the system: a real contract names people, addresses, salaries, deposits. The uploaded bytes exist only while a request is being parsed; afterwards only the extracted text and coordinates live in a session, until the reader deletes it or 30 idle minutes pass (refused from then on; the memory store frees it in a sweep within the following minute, the Redis store's key expires). In the Redis store every document and output is encrypted (AES-256-GCM under `SESSION_STORE_KEY`; the session id, the owner's uid and the field name bound in) before it is written, so the database, its provider and its backups hold no readable text, and a write to the database cannot hand a session to another reader: with the `owner` field rewritten, the values no longer open and the session is deleted. Compromise means one reader's contract seen by another, kept longer than promised, or sent somewhere it should not go (a log, an error message, a third party other than the model).
- **What the reader typed.** The interview's free-text answer is scanned in the browser for safety cues and never sent to the server, stored or shown back. It is the one input that could describe abuse or danger; the guarantee is that it stays in the tab.
- **The reader's identity.** A Firebase ID token in every API call and the uid it carries. The server keeps nothing about the reader but the uid on the session it opened. Compromise means acting as another reader (their session, their delete).
- **The model key.** `ANTHROPIC_API_KEY` (or the Replit AI integration's key), server-side only. Leaking it means spend on someone else's account; the client bundle is scanned for it before every submission.
- **The system prompt and pipeline lines.** Not secret, but their integrity is: the product's promise is that the model only restates selected excerpts and never advises. A document that talks the model out of that is the main attack on the product's meaning.
- **Availability of one process.** Budgets and gates, and with the default store the sessions, live in one Node process's memory. Exhausting it (memory, parser time, model concurrency) takes every current reader's session with it; with the Redis store the sessions survive the process, and the database's reachability becomes the dependency (`503 store-unavailable` while it is down).

Not assets here: passwords (Firebase holds them; the API never sees one), payment data (none), analytics (none), long-term storage (none).

## Trust boundaries

- **Browser → API** (`/api/*`). Everything from the client is untrusted: file bytes, names, MIME claims, the stage, the session id, the bearer token. The API re-derives what it needs (kind from magic bytes, ownership from the verified uid) and never trusts a client-side check.
- **API → worker thread** (`extraction/isolated.ts`). Parsers are the code most exposed to hostile input, so each document is parsed in a fresh worker with a timeout and a heap cap; the worker's failure modes are the API's `422`/`500`, never a crash of the process.
- **API → model** (`llm/anthropic.ts`). The prompt is data the API composes; the reply is untrusted text validated before anything is kept. Document excerpts cross this boundary as strings inside a delimited array, never as instructions.
- **API → Google's JWKS** (`auth/firebase.ts`). The only inbound trust the server extends: RS256 signatures against the keys Google publishes for the securetoken issuer, pinned to the project's `iss` and `aud`. No Firebase SDK or service account runs on the server.
- **Browser → Firebase Authentication.** Sign-in and token refresh; the document never goes there. What Firebase allows (providers, authorized domains) is configured in its console, not in this repository.
- **API → Redis** (`sessions/redis-store.ts`, `upstash-rest.ts`; only with `SESSION_STORE=redis`). The database is trusted to keep and expire keys, not to keep a secret: every document and output crosses this boundary sealed (`sessions/sealed.ts`), and only the owner's uid, the stage, the document type and the creation time are readable there. The ownership check, the capacity check and each write run inside the database (scripts), so a create, a lookup with its TTL touch, an output save and a delete are each one atomic step: another reader's request never moves a session's clock, and two uploads cannot both pass the cap. Every failed answer is a `503` with `Retry-After`; nothing is served from a guess. The database must be the API's own: the session cap counts its keys.
- **Public / signed-in.** Open: `GET /api/healthz`, `GET /api/sessions/policy`, and in the client the Welcome, sign-in, help, safety and not-found screens (none of them holds a document). Everything that touches a document needs a verified token, and every session route additionally needs the token's uid to match the session's owner; the client's route guards send a signed-out reader to sign-in and refuse a foreign `next` address (`tests/adversarial/route-guards.test.tsx`).
- **Development / production.** The mock model and mock sign-in exist for offline tests and the accessibility run; the server refuses to start with either when `NODE_ENV=production`, `REPLIT_DEPLOYMENT=1` or `VERCEL=1`; on Vercel it also refuses the memory store, which an instance-per-request host would lose sessions from. The dev gallery route is compiled out of production builds.

## Scan anchors

- Production entry points: `artifacts/api-server/src/index.ts` → `app.ts` → `routes/{health,documents,sessions}.ts`; the web client is a static bundle served at the artifact's base path.
- Highest-risk code: `routes/sessions.ts` (ownership checks, upload → extraction → session), `uploads/` and `extraction/` (hostile files), `auth/verifier.ts` + `auth/firebase.ts` (token verification), `llm/claims.ts` + `lib/grounding/src/validate.ts` (model output validation), `middlewares/` (budgets, gates, error shape).
- Public surface: `/api/healthz`, `/api/sessions/policy`, the static client. Signed-in surface: every other `/api` route. There is no admin surface.
- Dev-only: `artifacts/api-server/src/testing/`, `artifacts/api-server/src/llm/mock.ts`, `auth/mock.ts`, the client's `auth-mock.ts` and `pages/dev/`, `scripts/`, `tests/`. The stand-in providers are compiled into the bundles but cannot be selected: the server refuses to boot with either under `NODE_ENV=production` or `REPLIT_DEPLOYMENT=1`, and a production build of the client throws at start-up if it was built with `VITE_AUTH_PROVIDER=mock` (`features/auth/auth-client.ts`); the dev gallery route and the testing helpers are not in a production build at all.

## Threat categories

### Spoofing

A caller pretends to be a reader, or a token is accepted that Google did not issue. **Guarantees:** every document and session route MUST reject a request without a bearer token that verifies as an RS256 Firebase ID token for this project (`aud` and `iss` pinned, expiry enforced, uid from `sub`) with `401`; a token for any other project MUST fail; the mock verifier MUST be impossible to enable in production. Enforced by `auth/verifier.ts` and `auth/firebase.ts`, `lib/config.ts` (`isLiveEnvironment`), tested in `auth/firebase.test.ts` and `routes/sessions.test.ts`.

### Tampering

A client changes what the server does by lying about a file, a stage or a session, or a document changes what the model does. **Guarantees:** file kind MUST be decided from the bytes (`%PDF`, a ZIP with `word/document.xml`, text without NUL), not from the name or MIME type, with `415` on a mismatch; a file name MUST be treated as a label only (no path separators or control characters, `400`) and nothing an upload sends MUST ever be written to disk; the interview answer MUST NOT reach the server at all; the model MUST be able to return only a tool call matching the strict schema, and a claim MUST be discarded when its cited chunk does not exist, its quote is not found verbatim in that chunk, it echoes the prompt, or it fails the language lint. Enforced by `uploads/`, `extraction/`, `features/journey/flow.ts` (browser), `llm/claims.ts` and `lib/grounding`; tested by `tests/adversarial/upload-hardening.test.ts`, `tests/adversarial/prompt-injection.test.ts`, `lib/grounding/src/validate.test.ts`.

### Repudiation

Not a concern of this product: a reader's account is a Firebase identity the API never stores beyond the uid on an open session; there are no transactions, nothing shared between readers and nothing kept to dispute. Request logs carry a request id, method, redacted path and status so an incident can be traced, and deliberately nothing that identifies a reader or a document.

### Information disclosure

One reader sees another's document; a document or a key appears in a log, an error or the client bundle; a response carries more than the screen needs. **Guarantees:** a session MUST be returned only to the uid that opened it and any other reader's request for it MUST be a `404` (so ids cannot be probed and only the owner's delete does anything); API errors MUST be `{ error: { code, message } }` with no stack, path or file content; logs MUST carry redacted URLs (session ids replaced) and MUST NOT carry file names, document text or tokens; the model MUST see only the paragraphs selected for one field, never the whole document; the client source and production bundle MUST NOT contain a server secret name or an Anthropic key prefix; every string from the API or the document MUST be rendered as text (no HTML from data). Enforced by `routes/sessions.ts`, `middlewares/api-error.ts`, `lib/log-url.ts`, `pino` serializers in `app.ts`, `llm/claims.ts`, `scripts/check-client-bundle.sh`, React's text rendering; tested by `routes/sessions.test.ts` (foreign uid → 404), `middlewares/api-error.test.ts`, `tests/adversarial/xss-rendering.test.tsx`, `tests/adversarial/reader-switch.test.tsx` (the browser forgets the first reader's outputs when another signs in), `tests/export/packet-export.test.ts` (nothing of the payload's shape reaches the packet).

### Denial of service

One client, or a burst of readers, exhausts the process: a huge or malicious file, a parser that never returns, a flood of analyses each fanning out to model calls, or a session store that never empties. **Guarantees:** a request MUST be charged to its client address before anything is read (600 a minute across `/api`; uploads and analyses also against 60 a minute; `429` with `Retry-After` past that); uploads MUST stop at 10 MiB while streaming (`413`), before the type is looked at, and DOCX archives MUST be inflated under an entry and size budget; each parse MUST run in a fresh worker with a 30 s timeout and a 256 MB heap, and the process's resident memory MUST be watched so an extraction under pressure is stopped with an error rather than the server dying; admission MUST be bounded (32 uploads buffering, 2 extracting with 16 waiting; 4 analyses running with 16 waiting; `503 busy` beyond) and model calls MUST be capped process-wide (8 in flight, a bounded queue, `overloaded` past it); each model call MUST time out (30 s) and be aborted when its session is deleted; sessions MUST be refused once 30 idle minutes have passed and swept from memory within the minute after, and the store MUST refuse to open more than 100. Enforced by `middlewares/budgets.ts`, `middlewares/rate-limit.ts`, `middlewares/extraction-gate.ts`, `uploads/`, `extraction/isolated.ts`, `llm/concurrency.ts`, `llm/anthropic.ts`, `sessions/`; tested by `middlewares/*.test.ts`, `extraction/*.test.ts`, `llm/concurrency.test.ts`, `routes/sessions.test.ts` (TTL, busy), `tests/adversarial/upload-hardening.test.ts`. Budgets are per process and per client address as `TRUST_PROXY` resolves it; see *Accepted risks*.

### Elevation of privilege

A reader gains a power the product does not give anyone: another reader's session, the server's file system, code execution through a parser or a template. **Guarantees:** there MUST be no route that lists or searches sessions and no privileged role; ownership MUST be checked on every session route after authentication; no user-supplied string MUST reach a shell, a file path, an `eval`, or `dangerouslySetInnerHTML`; parsers MUST run in workers so a parser exploit is contained to a thread with no file-system use; the retention notice and everything else that reads server state MUST be read-only. Enforced by the route table (`routes/sessions.ts` has get/delete/three prepares by id only), the worker isolation, and the absence of shell/FS/HTML sinks (grep for `child_process`, `writeFile`, `dangerouslySetInnerHTML` in production code finds none); the upload suite checks the working and temp directories before and after hostile-name uploads.

## Accepted risks and their reasoning

- **Firebase web config is public and committed** (`.replit` `[userenv.shared]`, the client bundle). It identifies the project; it is not a credential. Firebase's own control is the authorized-domains list and the enabled providers. Recommended: restrict the web API key in Google Cloud console to the serving domains (HTTP referrers) so it cannot be reused from elsewhere.
- **Budgets are in-memory and per process.** Several instances each have their own budgets, analysis gates and in-flight de-duplication; the Replit deployment is one instance by design. Sessions are the one thing that can be shared, through the Redis store, which the Vercel setup (`docs/deployment.md`) requires; a delete there aborts only the model calls in flight on the instance that received it, while any instance's finished output is dropped rather than kept once the session is gone.
- **The sealing key is one secret for all sessions.** `SESSION_STORE_KEY` lives in the host's environment beside the model key; whoever holds it and the database's token can read live sessions for their remaining minutes. Rotating it retires every live session at once (they become unreadable and are deleted on their next lookup), which is the intended way to respond to a suspected leak.
- **Client address is the budget key.** Which address is decided by `TRUST_PROXY` (`lib/config.ts`, `app.ts`): off by default, so `req.ip` is the socket peer and a forged `X-Forwarded-For` is ignored (pinned by `middlewares/http-hardening.test.ts`), at the price that every reader behind one proxy shares its budget; a hop count or address list charges the address the trusted proxy appended; `true` believes the header as sent and is set only for the Replit deployment, whose edge replaces the header (observed 17 September 2026). A wrong setting for the proxy in front of the server lets a client pick a fresh bucket per request. Readers behind one shared address share one budget either way.
- **The validator proves location, not entailment.** A statement's quote is proved to sit in the cited paragraph; whether the restatement follows from it is what the reader checks by opening the excerpt, which the UI makes one press away. A model that paraphrases policy without eight words in a row is not caught by the echo guard; nothing in the prompt is secret.
- **No OCR.** Scans are refused rather than read badly; a misread contract is a safety risk in this domain.
- **No persistence, so no resume.** A reload loses the document on purpose; the browser deletes the orphaned session.
