# One call site, mechanical grounding

- "Supports the claim" (PRD §7.2) is proven by a verbatim `quote` the model must copy from a cited chunk; the validator checks normalised containment. **Why:** the claim text is a paraphrase, so containment of the claim itself is impossible, and lexical-overlap scoring is a judgement call nobody can explain to a judge. A quote is either in the paragraph or it is not, and the UI can show it. Location is never taken from the model; it comes from the first verified citation.
- Strict JSON via a *forced tool call* (`tool_choice: {type: "tool"}`), not Anthropic's structured-outputs beta and not the SDK. **Why:** works on every Claude model and on the Replit Anthropic proxy (same protocol, other base URL), ~120 lines instead of a dependency, and no sampling parameters are sent because the proxy's newer models reject `temperature`.
- Retry policy: one retry only for validator failures (bad JSON, schema, unfinished reply, any rejected claim), carrying the validator's `detail` lines; provider errors (429/529/timeout) fail fast on either call and are never dressed up as the first attempt's partial success (the review flagged that as concealing outages). If the retry is worse, the first attempt's verified claims stand; whatever still fails is withheld and counted, never dropped silently. **Why:** the task budget is two short calls per request under a 120 s request timeout; upstream retries/rate limiting are a separate concern.
- The output token cap is derived from the schema caps, and a cut-off or otherwise unfinished reply is treated as a validator failure (retry asking for less), never as a reason to raise the budget. Any non-`complete` stop triggers the retry even when the partial reply parsed; a truncated final reply's verified claims are returned (incomplete, not wrong), a refusal/filter stop (`other`) is never accepted.
- The mock provider reads the excerpt JSON array back out of the **last line** of the user message, so the prompt layout is load-bearing: keep the excerpts last or the mock test fails.
- Key source: a hand-set key wins over the Replit integration's provisioned pair; which one to provision is still the user's call. The retention notice promises "passages only" go to the AI service — the prompt sends the selected chunks, the task line and the reader's question, never the filename or whole document; keep it that way. Base URLs must be https except loopback.

- Prompt-leak guard: the validator withholds a claim that recites the `instructions` it is given (`instructions-echoed`), and the API passes everything fixed the model sees (policy, labels, tool name/description, schema descriptions) but deliberately not the task line or the reader's question. **Why:** the injection fixture's "reveal the system prompt" clause produced a claim reciting the policy that passed every other check; review-prompt task lines legitimately share wording with claims. Exact-run and exact-shingle versions were each beaten by a simple mechanical evasion (pieces across claims, one word altered every so often, filler words), so the check is an ordered local alignment with a documented residual: a recital altered every third word or a real paraphrase passes, and that is acceptable because nothing in the prompt is secret. Detail sentences must never echo the prompt themselves.

**How to apply:** new analysis routes call `generateClaims` with `SourceChunk[]` that carry ids and the registry's category keys; they map `ClaimResult` failures to ErrorResponse codes and never forward `error.message` or any prompt text.
