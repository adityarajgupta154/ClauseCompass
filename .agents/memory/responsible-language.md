# The table was derived; the lint is narrow on purpose

- PRD §8 / FR-06 *name* a Responsible Language table but never fill it in. The five registers (validity verdict, outcome prediction, eligibility conclusion, directive advice, fairness judgement) are ours, same precedent as the derived clause-rule table; flagged to the user on 2026-09-14. If they ever supply the original, reconcile rows into the one lexicon rather than adding a second.
- The lint runs over **product sentences only** — rule templates, model claim *text*, review copy — never over document text (quotes, places, paragraphs) and never over all of `copy` (the boundary statement itself would trip it). **Why:** contracts say "you will be entitled to 18 days" and "held to be invalid" as a matter of course; hiding or rewriting the document's words would break the verbatim-quote contract.
- Two-sided contract: the table must catch verdicts *and* let restatements through. Guards that exist for real fixture sentences: possessive `'s` is not a copula (contracted copula only after a pronoun); "held/found/deemed … to be invalid" is severability boilerplate; "to the extent/unless/where … legally permitted" is a carve-out; "check what you would be owed" is an inquiry, not an entitlement. A model *restating* "you will be entitled" stays forbidden on purpose — the retry teaches it to say "the letter gives you …".
- Negative lint is not enough for FR-06: a grounded, non-conclusory bare statement ("The deposit is three months' fee.") is a fact, not a prompt. The review call also passes a positive **review-register check** (question mark or an ask/check/confirm construction) through the validator's `register` option; the document map does not. **Why:** the architect review found the mock's "this passage begins …" text passed every golden while never asking anything.
- Enforcement is at every construction point: registry invariant check, validator rejection with one retry carrying the reason, builder assertion, and the system-prompt rule rendered from the same rows. Rendered-page spot-check (all fixtures × stages) shows hits only inside quoted document sentences.

**How to apply:** when a pattern change is needed, add the offending sentence to CAUGHT (or PASSES) in `language.test.ts` first, then broaden; the golden review-prompts suite pins zero violations and `withheld === 0` for the mock on every fixture, so it surfaces any new false positive on real contract sentences. Any new screen that phrases a sentence *about* the document routes it through the lint; if it is meant to prompt the reader, pass the register check too.
