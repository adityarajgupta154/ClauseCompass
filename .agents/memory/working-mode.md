# Build only the task in front of you

The one-task-per-turn rule itself is in replit.md (User preferences). The nuance that is not:

**Why:** The user's task breakdown carries its own acceptance checks per task; pulling UI or model work forward collides with that sequencing (the design pass belongs to their UI task, offline tests to their testing task).

**How to apply:** Map each task to its PRD section (docs/PRD.md), do it, flag prerequisites the task forgot, but do not pre-build what a later task obviously covers. Small enabling hooks are fine when the current task's semantics need them (a guarded placeholder route, the mock LLM provider in the env check). After each task: architect review round, fix severe findings, report in Hinglish.
